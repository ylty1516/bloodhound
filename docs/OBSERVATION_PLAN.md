- 范围：主服务现有 github-pow、github-nodes、github-tasks 三个公开 GitHub 搜索源，每源 1,800 秒；具体 URL 与开始、目标时间写入 observation.source_plan / start_at / target_at。
- 运行窗口：自然时间全天，共 168 小时。关机、休眠、断网和暂停产生的缺口保留，不延后分母或补造成功记录。
- 操作：只读 HTTP 采集、条件请求、规则去重和本地记录。监测本身不启动模型、项目软件或账户操作。每日 Agent 检查准入默认 2 次 / 120,000 tokens，未知用量预留 30,000；不是 CLI 单次生成硬上限。
- 通过条件：自然时间至少 168 小时，计划检查成功率至少 95%，无变化周期零新增模型调用；还须完成实际候选的独立抽查、错误分类与人工复核。到期只允许标为待审阅，不能自动 PASS。
- 当前范围只能证明这三个来源的采集可靠性，不证明全市场覆盖、可获利性或项目执行能力。每日聚合报告与质量抽样仍待补齐，缺少这些证据不能完成 P4 验收。
- 原有 mining-radar 服务与 automation-4 不修改；Prospect 使用自身单例服务和扫描锁。持续发现与观察共用一次调度，不重复扫描。旧外部服务是否恢复仍需独立记录，不伪称统一接管。

持续发现开关与观察计时分开保存。暂停全部自动采集，需要在“来源与证据”关闭持续发现，并在“总览”暂停七日观察；或在工程目录执行 `python -m prospect stop` 停止 Prospect 服务。停止期间计入覆盖缺口。服务再次启动会按已保存状态继续，只读取到期来源。

实际启动摘要见 `evidence/core-observation-start.json`，扫描账本保存在 `%LOCALAPPDATA%\Prospect\prospect.sqlite3`，运行日志为同目录 `service.log`。这些运行文件及控制凭据不搬入保存库。
