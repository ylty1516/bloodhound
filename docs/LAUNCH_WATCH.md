## 当前规则

寻找已经公布挖掘消息、主网尚未开放挖掘的虚拟货币。主网开挖和代币上市是两件事；测试网已经运行也不代表主网已经开放。项目原生 PoW 钱包、币安兼容的代币路线以及其他钱包路线均可跟踪，不因尚未交易、经济价值未知、设备不匹配或安全审阅未完成而丢弃公告。

发现符合信号的公告后立即持久化重点待办，不等待用户表达意向或 Agent 完整审计。CPU 排在最前，CPU/GPU 均可的路线其次，同属 CPU 优先层；然后为 GPU、设备待核实、ASIC。设备方向以公告证据为准，不根据本机显卡猜测。

有一手主网未开放说明或明确未来时间的条目标为待开挖；第三方消息、缺少时间、日期冲突等先标为待核实，不能当作已确认事实。只有“coming soon”的普通软件改版、数据挖掘资料、已开放挖矿及只有测试网任务的条目不能冒充主网预告。

待办是信息跟进，不启动矿工、钱包、签名或资金操作，也不表示安全或盈利。安全检查仍在实际执行前单独完成。已经开放的 unMineable 试跑记录保留在运行中心，不再作为“未开挖新机会”展示。

## 使用与变化处理

- 左侧 **开挖待办** 是固定入口；总览和开始参与页顶部也显示重点提示。卡片包含设备方向、公告来源、主网时间（北京时间）、钱包情况和待核实信息。
- “让当前 Agent 核对”沿用当前宿主自动识别和真实进度，不要求用户手选宿主。Codex / Claude Code / pi / DeepSeek Harness 共用相同报告与待办接口。
- 同一公告重复轮询只维护一个任务，不因检查心跳重建待办或反复生成事件。论坛回复按 topic ID 归并；不同来源的同名币不自动合并，跨来源身份需核验。
- 可设为跟进、标为完成，并在“已处理 / 全部记录”恢复。后续轮询不覆盖用户的处理状态；原始来源、时间变更与发现事件保留。
- 到了公告时间只标为“时间已到，待核对开放”，不把倒计时结束当作已开挖。来源三天没有成功复核则标为需要重新核对；有正式开放或取消报告后保留原任务并更新阶段。
- 一手证据不会被后来的未核实社区简介覆盖。日期不含时区或存在冲突时保持未知，不猜测 00:00。

## 接口与验证

- `GET /api/launch-watch`：重点任务、来源说明、CPU/GPU 排序、实际扫描状态。
- `POST /api/launch-watch/decision`：处理本地任务状态，需要本地会话。
- `POST /api/launch-watch/report`：仅可信本地 Agent 适配器可提交带来源的开挖消息，网页会话不能提交 Agent 报告。
- `prospect_launch_watch` / `prospect_launch_report`：四宿主共用工具。`prospect_status` 也返回 `priority_todos`；原有 Agent 检查报告可附 `mining_launch`，完成报告与生成待办在同一事务中保存。

工具共 28 个；新包 `adapters/prepared-v11/`。已安装桥接可更新而不修改 hook 信任；已运行的宿主可能需要重新加载新工具。四端接口读取通过不等于每个原生宿主都完成完整启动 / 模型 / 恢复验收。

完整 Python 回归 225 项通过（`evidence/launch-watch-final-release-tests.log`），覆盖未定价原生币自动入待办、CPU 排序、重复轮询、处理状态恢复、过期 / 延期 / 开放边界、日期时区、来源权限、四宿主报告入口和异步扫描。Headroom 将 231 行日志压缩到 7 行，stats 估算节省 8567 tokens。规则采集和待办整理不调用模型；用户主动 Agent 核验另计用量。
