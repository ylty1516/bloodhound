# 尝试建议与 Agent 模型设置

2026-11-07。用户要求安全通过即可考虑尝试，硬件暂不用于筛除，并提供专门的模型设置页。

## 新的判定

旧实现把任何 topic 的 fail 或本机规则不兼容合并为 unsuitable。这会把安全问题、内存不足、维护时间及费用限制混为同一结论。现在 `recommendations.py` 单独计算尝试建议，保留报告原文及 `agent_verdict`，历史报告不改写。

- 建议尝试：具体候选入口和所列范围的安全检查通过（运行软件须固定版本），有引用依据，风险检查通过，未确认参与已关闭。
- 待安全核验：缺少版本、范围或足够依据；网页风险搜索不能自动升级为代码安全审计通过。
- 存在安全问题：风险检查或安全审计明确失败，展示具体发现。
- 参与窗口已关闭：记录确定的关闭状态。
- 需要更新安全检查：项目资料有变化或安全通过记录超过48小时。设备变化不单独取消尝试建议。

硬件、费用、技能、维护时间和市场状态作为独立提示；已上市仍清楚标注，不冒充未开盘。安全通过的条目进入“建议尝试”并生成参与请求，不再通过旧的硬件/未发行筛选器。意向按安全证据修订去重。实际运行准备和模拟仍会检查设备与配方，建议不产生安装、签名或资源使用授权。

报告新增可空的 `safety_audit`：status、method、target_url、version、scope、findings、sources。软件/脚本的source_review需要固定版本、范围和报告中已声明的公开HTTPS来源；入口须与候选匹配。官方网页任务可用official_web，核验身份、入口、权限和凭据处理，不强求网站源码或软件版本；该方法不用于节点/挖矿软件。审计范围、未覆盖部分由 Agent 如实说明，服务只验证结构与一致性，不声称完成了独立全面审计。旧报告没有此字段时继续可读，不能自动获得安全通过标记。

## 模型页面

入口为 `http://127.0.0.1:18766/#agents`，左侧“Agent 与模型”。

- Codex / Claude Code 原生后台检查支持模型 ID、思考强度、默认宿主，存入 Prospect 自己的数据库。
- Codex 模型提示来自本机 models_cache.json，按目录声明校验思考强度；允许输入有效格式的自定义 ID。目录存在不等于当前账户已经验证可用。
- 单独显示宿主偏好，仅提取模型/强度白名单字段；不读取认证文件，不改宿主设置、不传出配置文件。
- pi / DeepSeek 当前通过已运行宿主领取；页面明确由宿主会话管理，不提供无效的远程改模型控件。
- 每次请求冻结配置，保存只影响下一次新检查。进行中的任务不因改配置重复启动；完成缓存不会掩盖配置变化。
- 任务记录区分请求配置和原生事件回报的实际模型。未回报保持未知，旧任务不根据当前配置倒推。思考强度显示传给 CLI 的请求值，不伪称服务端回报。
- 新原生命令按设置传入 `--model` 和思考强度参数；Claude 同时设置子进程的 effort 环境变量，避免宿主环境优先级使页面选择失效。使用参数数组，不拼接 shell 命令。

本机默认已显式设置 Codex `gpt-6.1-sol / medium`，自动选择仍优先 Codex；Claude 保留原来的默认模型/low。用户可以修改或填入宿主偏好。预算保持不变，保存不调用模型。

实现依据：[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)、[Claude CLI 参数](https://code.claude.com/docs/en/cli-reference)、[Claude 模型与 effort 优先级](https://code.claude.com/docs/en/model-config)。本机核对 Codex CLI 0.154.0、Claude Code 2.1.218；Codex 的 max 等选择也与本机模型目录核对。未开放带自动多 Agent 编排的 ultra/ultracode。
