# 面向新手的设备方向和运行准备

2026-11-08。用户需要更简洁的操作、CPU/GPU方向，以及看懂为什么项目不能运行。

开始页现在只有一个主操作区：优先列出已接入路线，显示设备方向、能否运行、由谁处理阻碍和下一步。过去选中的未接入项目仍可看见，并可一键换到已有路线。历史检查、参与请求和完整准备方案收入默认折叠区；市场、设备门槛和来源在详情中折叠。正常模式只显示自动识别出的Agent，不重复说明宿主技术细节。

发现页改为“发现线索”，表格保留项目、CPU/GPU、能否运行、下一步。未接入项目标“仅线索 · 不能启动”，按钮为“查看资料”；已接入项目才进入运行准备。新增CPU/GPU/轻量任务筛选。CPU/GPU字段描述项目方向，不能当成设备收益排名。

## 设备依据

Agent报告新增可空的compute_profile：priority为cpu/gpu/either/none/unknown，reason为新手中文说明，sources必须引用报告已有证据。缺少来源不能标为CPU/GPU已判断，旧报告仍兼容。固定执行路线能证明本软件当前使用CPU；其他未核验项目只能从简介中提取“CPU/GPU方向 · 待核实”线索，没有资料则明确待确认，不根据用户显存配置猜测。

本轮只读核对[官网](https://opacra.org/)的CPU说明，以及[v1.0.0测试网发布页](https://github.com/opacra/opacra/releases/tag/v1.0.0)的版本、哈希和测试币说明。与现有固定配方一致。来源核对不是程序安全审计，不能据此生成安全通过记录或开放真实启动。

## 实际运行准备

Executions.readiness与运行preview共用同一套固定配方、版本、程序哈希、审阅范围、建议状态和系统检查。页面不能只因Agent说“适合”就显示可运行。软件未接入、需要Agent继续安全核验、发现风险、可打开运行设置分别显示；不再把运行功能缺失归咎于用户的链上经验或硬件知识。硬件方向仍不作为建议尝试的拒绝条件。

真正准备好的路线可直接打开推荐运行范围：默认60秒、CPU最高20%、内存最多2048MB、电脑空闲时开始。时长/资源设置和程序来源默认折叠；节点试运行明确不需要钱包。真正启动仍需用户确认一次，不从页面选择或资料检查自动开始。

正式数据复核：67条发现中，0条可设置运行、1条已接入待安全核验、65条未接入、1条有安全问题。当前CPU测试网路线缺对应版本的安全通过记录。没有运行真实加密项目，也没有新增模型检查。开发完成度不足仍然存在，界面修改不代表已交付完整挖掘路线。
