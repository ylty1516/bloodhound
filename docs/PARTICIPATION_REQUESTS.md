# 主动参与请求

2026-11-07更新：尝试建议采用安全优先策略，硬件不再筛除推荐；模型可在独立页面配置。以 [最新策略与模型说明](TRIAL_POLICY_AND_MODELS.md) 为准，下文旧的全条件筛选描述保留为历史实现背景。实际执行条件仍独立检查。

用户在 2026-11-06 要求：发现高价值目标后，主动向用户提出挖掘/参与请求。这里的高价值表示值得审阅参与计划，不表示确定收益或代币价格预测。

流程：公开线索 → 宿主提交带一手证据的研究结论 → 规则评估 → 持久参与请求 → 页面提示/宿主工具提示 → 用户表达意向 → 后续形成具体授权与执行计划。

仅有 GitHub 仓库、营销描述或未查到现货信息不足以触发请求。自动规则要求当前修订的研究任务已 resolved，近期官方证据、明确开放窗口、目标市场状态及充分的资源要求；硬件不满足的项目不进入请求。用户的预算、技能等尚未填写时可在请求中列为待确认，不因此伪造值或一概隐藏潜在机会。

首页和参与请求页显示理由、资源、维护时间、已知成本、奖励性质、证据、待确认项。积分不当作到账代币；未知成本不当作免费。网页对新请求做一次提示并持续显示待处理数量；关闭网页时不声称能够推送桌面通知。

宿主通过现有 prospect_research_resolve / prospect_status 得到紧凑请求及向用户展示计划的提示。启动 hook 仍只唤醒服务，不强行唤起模型，也不修改已经信任的 hook。此版本没有在关闭聊天后自动发起宿主对话的能力。

同一个项目的相同实质修订只有一份请求，单纯更新核查时间不重发。暂不参与会持久保存；来源/资格不再符合时，待处理或有意请求变为 stale，不能接受旧计划。重新研究且同修订恢复符合条件时，恢复过期前状态，不重复产生新请求事件。点击有意参与只保存 interested，execution_authorized 始终为 false；没有矿工、交易、钱包或新的系统任务被启动。

网页的首次通知按本浏览器 localStorage 中的请求 ID 去重。宿主工具要求在当前会话内不要重复呈现已展示的 ID；目前尚无跨宿主会话的送达确认账本，不能承诺所有聊天渠道都只提醒一次。

2026-11-06：Agent 报告中的结构化事实通过校验后更新资料并解决当前研究任务，自动评估提请资格；风险不通过的结果被排除。当前聊天提交带来源的研究报告也可复用。未达到提请资格的报告仍出现在“检查后的准备方案”，显示缺项或不推荐原因，不代表高价值目标或运行授权。

## 运行记录修正

此前四条 Verge blocked 记录是开发者 browser-qa.mjs 点击模拟按钮产生的预检结果，发生于 2026-11-06 UTC 11:32:20、12:02:53、12:04:07、12:04:48。它们没有运行真实项目。脚本 scripts/annotate-historical-qa.py 仅针对明确的四个 ID 和时间进行身份核对，在独立 run_annotations 表中附加 origin=validation；原始 runs 内容保留。

默认页面将开发验证与用户预检分开，仍可查看原始验证结果及具体缺项。其他用户记录不会因 blocked 状态而被归入验证。真实页面 QA 今后只读，模拟和请求动作测试使用独立数据库。

## 接口

- GET /api/state 新增 participation_requests，run 可以包含 origin/origin_note。
- POST /api/participation/decision 接受 {id,decision}，decision 仅为 interested 或 dismissed；沿用本机鉴权和同源限制。
- 采集、研究、硬件、档案更新后会重新评估；读取状态也会检查陈旧条件。生成与决定均持久化，并在 events 留痕。

完整自动监测仍取决于实际扫描调度和研究证据；当前后台没有付费模型执行器。此改动不代表七天观察或真实项目执行已经通过。
