# Codex 检查失败与来源锁定修复

2026-11-09，本机现场核验。

## 失败原因

Prospect 原先优先调用独立目录中的 Codex CLI 0.154.0。当前桌面应用自带 0.167.0-alpha.3.2，模型目录也来自新版本。旧 CLI 请求 `gpt-6.1-sol / medium` 时，经过多次连接重试，最终返回 `model_not_found`，错误说明该调用方式下 ChatGPT 登录不支持所选模型。这是本机这条旧调用路径的结果，不能扩展成所有 Codex 或该账号永远不支持此模型。

改用已安装的桌面随附 CLI、保持相同模型与思考强度后，真实最小请求成功返回结构化结果。没有安装新客户端、切换模型、创建 API key 或改动登录凭据。之后正式检查进入了搜索和读取阶段，证明它已越过原来失败的位置。

第一份正式返回又因参与状态字段不符合约定而未通过软件校验；当时只保留了 `Invalid participation fact`，不能还原或捏造具体的错误值。旧实现还漏掉了 Codex 标准输出中的错误事件，因此原页面只展示笼统的网络 / 额度提示，无法准确区分原因。

## 修正内容

- 在桌面随附、独立安装和 PATH 中识别已安装的 Codex，比较实际版本，选择较新版本；缓存结果，避免网页每次刷新都运行查找与版本探测。
- 子进程沿用用户现有 Windows 系统代理，保留显式环境配置，并在已验证支持的版本启用尊重系统代理的功能。没有修改系统代理、关闭 TLS 校验或扩大项目执行权限。
- 捕获 `error`、`turn.failed` 及错误条目，给出模型权限、连接、格式、登录或额度的分类说明；重试事件显示真实重试进度。本地线程启动只表示等待模型响应，不再声称模型已连接。
- 请求模型与思考强度保持原值；运行记录补充实际 CLI 版本和来源。服务端没有回报实际模型名称时继续显示未知，不从请求名推断实际型号。
- 报告结构约束与事实校验对齐：参与状态只接受 open / closed / unknown，主网未开挖另用 mining_launch.status；市场和技能事实也使用相应枚举。
- 报告格式不通过时保留已经取得的真实用量，未采纳的结构化报告仅保留在私有 `agent-check-work/<id>/report.json`。不会因为格式错误就采纳事实、自动授权执行，或把未知用量记成 0。原生 CLI 的原始输出和认证诊断不进入保存库。
- 旧七日观察已暂停时允许调整当前来源，同时保留原始观察计划。运行中的观察仍要求先暂停；配置改变后不能直接续接旧计划冒充同一次观察。实际来源开关没有被本次修复替用户改变。
