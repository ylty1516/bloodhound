# 手动检查与后台自动预算

2026-11-08。原来统一套用每天2次/120000 tokens的本地准入预算，失败未回报用量也占次数，导致用户主动检查和重试被“今日检查额度已用完”阻止。该限制由Prospect设置，不代表Codex或DeepSeek账户额度。

现在网页、原生工具与MCP用户入口发起的任务默认 `origin=manual`，不设本地每日次数或token上限。失败仍保留次数、错误与用量记录，但不会据此停止手动重试。主流程、项目详情的额度禁用逻辑已移除；同一活动任务/已完成报告仍按原规则复用。单次输出参数、任务超时、并发和服务商账户自己的限制不变。

内部后台研究任务必须显式调用 `AgentChecks.request(..., origin='automatic')`，领取时才按自动检查预算准入；未回报自动用量保留预留。手动用量不会挤占自动预算，自动预算耗尽也不阻止手动检查。等待中的自动任务收到用户主动继续请求时转为手动并复用任务，不重复派发。旧任务缺少origin字段时视为手动，因本轮前全部检查入口都是用户发起；不删除或重写历史报告。

`agent_budget`响应保留全体已开始次数/已回报用量统计，并新增 `manual`、`automatic` 两组和 `scope=automatic_checks`。旧顶层 `can_start`/`remaining_checks`仅表示自动准入，手动许可为 `manual.can_start`（以及manual_can_start）。手动未回报标记为未知，不伪装为零用量；手动任务不占自动预留。

“档案与设置”中的表单改名为“后台自动检查预算”，明确手动检查不受其限制。当前持续采集本来就是规则模式，没有新增自动模型调度或付费任务。

验证：完整170项Python回归通过，含5项手动/自动预算边界测试、新增HTTP端到端领取测试、更新的自动预算测试；DeepSeek模拟HTTP流在自动预算为0时仍可完成手动检查并记录用量。22项参与状态断言及4项原交互检查通过。隔离5716服务以自动预算0、两次已失败手动检查开始，浏览器第三次手动提交和原生领取均成功；受控失败后仍可重试，未调用模型。
